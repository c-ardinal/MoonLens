# Changelog

All notable changes to MoonLens are documented here. The format
follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and
the project adheres to [SemVer](https://semver.org/).

Unreleased changes live as one file per change in
[`changelog.d/`](changelog.d/README.md) and are folded in here when a
version is tagged. Do not edit this file in a feature PR.

### Changed

- New app icon: a copperplate-engraving style "moon lens" (parchment and ink, two colours). Sizes up to 32 px and 48–64 px use simplified drawings so the icon stays legible in the taskbar and tray. Sources are in `src-tauri/icons/source/`.

## v0.1.0-rc.1 — 2026-11-18

First release candidate: Windows, macOS (Apple silicon) and Linux
installers for testing on real machines.

### Added

- Live translation. The selector's "ライブ" button (or the pin
  shortcut) keeps translating the selected region in place on the live
  screen: translations are painted over the source text in a
  click-through window that follows the content as it changes
  (subtitles, chat, game dialogue), instead of showing a popup beside
  the region. A translation whose source area changes is hidden at
  once, before OCR runs again; text that is the same as before (a video
  behind a subtitle) is not re-translated; text still being typed out
  is translated once it reads the same twice; paragraphs seen before
  come from the translation cache. The window is excluded from screen
  capture on Windows / macOS, so it never reads its own translations
  (on Linux it is hidden for the moment of each capture). Uses the
  selector's target language. The pin shortcut stops it.

### Performance

- Local translation, explanation and summaries run on the GPU on
  Windows and Linux. The built-in llama.cpp now includes its Vulkan
  backend there (NVIDIA, AMD and Intel GPUs through the installed
  driver; macOS already used Metal), where releases used to run models
  on the CPU only. Without a usable GPU nothing changes: on Windows
  `vulkan-1.dll` is delay-loaded, so a PC without a GPU driver still
  starts and translates on the CPU, and a model that does not fit in
  GPU memory is loaded on the CPU instead of failing. The log names the
  GPU in use. Building now needs the Vulkan SDK (see README).

### Fixed

- No window ever received an event in a real build: without a capability
  file Tauri rejects every plugin call from the webviews, including
  `listen()`, so the selector never got its frozen frame, translations
  did not stream and settings changes did not reach other windows. Added
  `src-tauri/capabilities/default.json`.
- The first launch showed nothing (the main window starts hidden and only
  the tray could open it; some Linux desktops have no tray). Every launch
  now shows the main window; `--hidden` starts in the tray.
- A second launch started a second tray icon whose shortcuts all failed;
  it now focuses the running instance.
- Closing the main window destroyed it and the tray "表示" item then did
  nothing. Closing now hides it. The frameless window also gained a
  draggable title bar with minimize / close, and the command palette a
  quit command.
- The QR "開く" button sent the decoded URL to Google's image search. It
  now opens the URL itself (http / https only).
- With no OCR model installed a capture said "テキスト未検出"; missing
  translation / OCR / assistant models, timeouts and unsupported CPUs now
  show a Japanese message, with a "モデル準備" button where a download fixes
  it.
- Pinning from the selector showed nothing (the floating overlay stayed
  hidden). Pinned results now appear beside the region, never over it.
- Live subtitles dropped audio while a chunk was being recognized (the
  capture queue held under a second), and decoded silence into stock
  phrases. The queue now holds ~40 s, a backlog is recognized in one
  window, and silent chunks are skipped. Starting from a shortcut or the
  tray now runs the same model check as the start button.
- Live subtitles without a whisper.cpp server opened the subtitle window
  and repeated an English error every few seconds. Starting now checks the
  server first, and three failures in a row stop the subtitles.
- Saving the settings screen reverted a model picked in the model list
  while the screen was open (and hand edits to `config.toml`).
- History search only looked at the newest 500 entries.
- A broken `config.toml` reset every setting and the next save overwrote
  the user's file; a corrupt history database stopped the app from
  starting. Bad values are now dropped one by one, the original file is
  kept as `config.toml.broken-<time>` / `moonlens.db.broken-<time>`, and
  the home screen says so. Shortcut registration failures at startup are
  shown there too.
- A `config.toml` missing a section got Rust's empty defaults (e.g. no OCR
  chain) instead of the bundled ones.

- The pin hotkey, the history hotkey and the command-palette hotkey did
  nothing (their events went to a hidden window or had no listener). The
  pin hotkey now pins or unpins the last translated region.
- One shortcut that could not be registered (taken by another app, or
  malformed) stopped every later shortcut from registering, and at startup
  stopped the app. Each shortcut now registers on its own and the
  settings screen names the ones that failed.
- Long text and paths overflowed history cards, model rows and plugin
  cards in narrow windows; layouts now wrap down to the 720 px minimum.
- The app's own styling never loaded: Tailwind v4 ignored
  `tailwind.config.ts`, so every design-token class (accent buttons, muted
  text, rounded cards, shadows) compiled to nothing and unlayered element
  resets stripped padding and backgrounds from every button.
- Ollama translations were slow or blank. The seeded model
  `gemma4:7b-instruct-q4_K_M` does not exist (404 was treated as an empty
  success); thinking-capable models reasoned before every answer because
  `think` was never sent; the 3 s translate timeout cut paragraph-sized
  OCR text off mid-stream; and the model was unloaded after 5 minutes.
  Requests now send `think: false` and `keep_alive = "30m"`, the model is
  preloaded at startup, HTTP / stream errors and empty answers fall
  through the chain with an actionable message (`ollama pull <model>`),
  and the translate timeout is 15 s. Existing `config.toml` files that
  still hold the old seeded values are upgraded at load.

### Changed

- Long captures show their first translation much sooner. With the
  built-in translation model the selection is translated in parts: a
  small first part (so the first lines appear after about 0.5 s instead
  of after the whole screen has been read), then larger parts. Every part
  is translated with the earlier parts and their translations as history,
  and the first part with the text that follows it as context, so
  headings and short labels keep their meaning (translation quality was
  measured to be unchanged; see docs/translation-latency.md). Parts are
  also short enough that large captures no longer hit the 15 s time
  limit. When a part comes back with a different paragraph count, only
  that part is retried block by block, and those retries keep the
  context too. Other translators still get one request.

- `config.toml` now stores only the values that differ from the bundled
  defaults (plus `config_version`), so improved defaults reach existing
  installs; `config.default.toml` next to it lists every default. Files
  are written atomically.
- Models moved to the app's local data folder
  (`<local data>/io.moonlens.app/models`; `%LOCALAPPDATA%` on Windows), so
  uninstalling with "delete app data" removes them. The old
  `moonlens/models` folder is moved over on first launch.
- Model downloads check free disk space first, report network / disk /
  integrity failures in Japanese, and deleting a model asks to confirm.
  Model files no catalog entry owns are listed for deletion.
- The settings screen has a "データ" section with folders and sizes, and
  refuses to save two actions bound to the same shortcut.
- The global cloud switch defaults to off and the reverse-image-search
  chain (Google / Bing / Yandex) is empty; existing configs are migrated.
- Lifecycle case matrix: `docs/lifecycle.md`.

- Settings that were stored but ignored now work and are on the settings
  screen: history retention (`storage.retention_days`, `max_entries`;
  applied on every save, at startup and when settings change), log level
  (`privacy.log_level`, unless `RUST_LOG` is set), translation-cache
  lifetime (`performance.cache_ttl_seconds`), and the popup's look
  (`overlay.font_size_px`, `line_height`, `max_width_px`, `opacity`,
  `blur_px`, `saturation`, `auto_hide_ms`).
- Settings screen rebuilt. It showed raw JSON for every section (the
  generated schema form never followed `$ref`), overflowing the window by
  2,000+ px. Settings are now grouped (翻訳 / モデル / ショートカット /
  ライブ字幕 / ピン留め / クリップボード / 履歴 / 外観 / パフォーマンス) with
  Japanese labels, help text, per-field reset, search, a save bar, and a
  key recorder for shortcuts. Fields the app does not act on yet, and
  cloud / network switches, stay in `config.toml` only.
- Theme, density, accent colour, reduced motion and subtitle font size /
  original-text display apply as soon as settings are saved
  (`moonlens://settings-changed`).
- Every main page shares a menu bar; the command palette works on all of
  them and from its global shortcut. Shortcuts are shown as Ctrl+… on
  Windows / Linux instead of ⌘.
- Home screen: "範囲を選んで翻訳" / "画面全体を翻訳" open the Lens selector
  (the main window steps aside first), and a banner points to missing
  models. Model downloads moved to 設定 → モデル, with OCR install state.
- Removed the reverse-image-search action and hotkey registration: they
  sent captures / text to Google, Bing or Yandex.
- Translation prompt names the languages ("from Japanese into English"
  instead of "from auto to ja"), keeps blank-line paragraph breaks, and
  tells the model to treat screen text as content, never instructions.
- Ollama default model is `gemma4:e4b`; PLaMo 3 Translate models are
  driven with their native PFML3 prompt (`raw`, tag stop tokens).
- `docs/translation-models.md`: benchmark of 10 local models (WMT22
  ja↔en + MoonLens-style cases). PLaMo 3 Translate 2B matches Gemma 4
  E4B quality at 2.5x the speed and resists prompt injection; it is the
  recommended translator. Reproducible with `bench/translation/`.

### Release packaging

- macOS (Apple silicon) `.dmg` is built on tag push next to the Linux
  and Windows installers. Ad-hoc signed (Gatekeeper asks once), macOS
  11 or later, and `Info.plist` declares the microphone use of live
  subtitles (macOS terminates an app that opens an input device without
  it).
- `tauri build` refused to bundle (the release workflow would have failed
  on the first tag): `@tauri-apps/api`, `plugin-shell` and
  `plugin-global-shortcut` were on older minor versions than their Rust
  crates. Bumped to match; `scripts/check-release.mjs` now checks this,
  the app version in all three manifests and the tag on every PR and tag.
- Installers include `THIRD_PARTY_LICENSES.html` (licence texts of all
  bundled Rust crates, npm packages and llama.cpp, plus the model
  licences) and the release attaches it. Generated by
  `scripts/third-party-licenses.mjs` with `cargo-about`.
- Releases are created as drafts with Japanese install notes; the unused
  updater manifest is no longer generated (no auto-update, no network).
- The project licence is MIT everywhere (`Cargo.toml` and the README
  said Apache-2.0 while `LICENSE` is MIT).
- README: install, first launch, shortcuts and uninstall guide.

### Removed

- The selector's "検索" button (opened a Google web search). MoonLens is
  fully local and does not hand text to web services.

### Added

- Live subtitles recognize speech with a built-in whisper.cpp; no
  external server has to be started. Whisper large-v3-turbo (default)
  and small are downloaded from the settings model list (SHA-256 pinned,
  resumable). whisper.cpp shares ggml with the built-in llama.cpp, so
  the GPU backends of the translation engine serve it too, with a CPU
  fallback. An external whisper.cpp server stays available as an
  optional provider.

- Overlay typography closer to the source: centred headings stay
  centred (alignment inferred from the OCR line edges), bold source text
  (headings, buttons) is drawn bold (stroke-width estimate, separate
  thresholds for CJK and Latin), and Japanese translations wrap between
  phrases without starting a line with small kana or closing punctuation
  (`word-break: auto-phrase`, `line-break: strict`).

- Translation cache. Each paragraph's translation is kept in memory
  (per target language, up to 2,000 paragraphs) so re-selecting the same
  text, scrolling back, or a pinned region re-rendering shows the
  translation instantly; only paragraphs not seen before go to the
  model. Cleared whenever settings / providers change.

- Built-in local LLM engine: translation, explanation and summaries now
  run in-process through llama.cpp (`llama-cpp-2`, statically linked),
  so Ollama is no longer required. Translation uses PLaMo 3 Translate 2B
  by default (`llamacpp`; 0.8B as the fastest option), explain /
  summarize use Gemma 4 E4B (`llamacpp.assistant`; E2B optional). Models
  are downloaded from the home screen; files are SHA-256 pinned, downloads
  resume after interruption. The model stays resident, is preloaded at
  launch, and the KV cache of the shared prompt prefix is reused between
  requests. Metal on macOS; `llm-vulkan` / `llm-cuda` features are
  opt-in.

- Target language in the selector. Text that is already in the target
  language (detected from its script, plus English function words for
  Latin text) and text without letters (prices, times) is no longer sent
  to the translator and stays uncovered in the overlay, so a Japanese
  screen no longer round-trips ja→ja. The toolbar shows the detected
  source language and a target-language menu; changing it re-translates
  the same OCR result without re-scanning, and the choice is remembered
  for the next selection. New command `retranslate_selection`.

- Japanese / Chinese OCR: new `ppocr` provider runs PP-OCRv5 mobile
  models (detection + recognition) on rten. It reads kana, kanji,
  simplified/traditional Chinese and English, and is now first in the
  default OCR chain (`["ppocr", "ocrs"]`), falling through to ocrs until
  its models are installed. Configs still carrying the old seeded chain
  `["ocrs", "paddle"]` are upgraded automatically. "モデル取得" installs
  both engines; the PP-OCR bundle is verified against a pinned SHA-512.
- `cargo run --example ppocr_bench -- <image>` benchmark.

- Lens-style in-place translation. The capture hotkey now freezes the
  monitor under the cursor, you select on the still image (or click to
  translate the whole screen), and each paragraph's translation is
  painted over the original text with matching background / text
  colours. Toolbar: original ⇄ translation toggle, copy, selectable text
  panel, explain, search, pin. `Esc` closes.
- Translation streams into the paragraph boxes as tokens arrive.
- OCR returns real line bounding boxes; lines are grouped into
  paragraphs (columns and headings stay separate, wrapped lines are
  joined, CJK-aware) and translated in one request so sentences keep
  their context.
- `cargo run --example ocr_bench -- <image>` prints OCR timings, lines
  and paragraph blocks for a screenshot.
- Glossary and Japanese style (設定 → 翻訳). Glossary entries fix how a
  term is translated, per target language; only terms found in the text
  are sent with a request. The style picks 敬体 (です・ます) or 常体
  (だ・である) for Japanese output. PLaMo 3 Translate receives both through
  its native PFML3 `glossary` element and `form` attribute; chat models
  (Gemma, Ollama) get them as one extra system-prompt paragraph. With an
  empty glossary and the default style, prompts are unchanged.


### Changed

- Default translate / explain / summarize chains are fully local
  (`["llamacpp"]` / `["llamacpp.assistant"]`, cloud and network
  disabled). Configs that still carry
  the old seeded Ollama + cloud chains are moved to the built-in engine
  automatically; the Ollama, DeepL and Gemini providers remain available
  for anyone who adds them to a chain.

### Fixed

- Legacy `.rten` ocrs models could not load after the rten 0.28 upgrade
  (the `rten_format` feature was off).
- Paragraph grouping: a wide paragraph no longer swallows a column to
  its right, and paragraph breaks are detected from the block's own line
  spacing and from short last lines (CJK line spacing no longer splits
  wrapped lines).
- OCR model download: upstream removed the `.rten` model files (403),
  so fresh installs could not OCR at all. Models are now the `.onnx`
  files (ocrs 0.14 / rten 0.28); existing `.rten` installs keep working.
- OCR reloaded both models from disk on every capture; the engine is
  now cached for the life of the process.
- `tauri dev` / debug builds ran OCR unoptimised (~30 s per capture on
  a 820×360 screenshot); the ML crates are now optimised in dev too
  (~0.6 s).
- QR decoding never ran with the default config because `rqrr` had no
  `[providers.configs]` entry. Built-in providers referenced by a chain
  are now registered with defaults.
- Multi-monitor: the selector opens on the monitor under the cursor
  instead of always the primary one.

### Added (release workflow)

- Tag-driven release workflow (`.github/workflows/release.yml`) that
  produces `.dmg` / `.msi` / `.nsis` / `.AppImage` / `.deb` / `.rpm`
  bundles for every `v*` tag. `-rc` / `-beta` / `-alpha` suffixes
  publish as GitHub pre-releases automatically.
- `docs/RELEASING.md` documenting the end-to-end release flow.

### Changed (release workflow)

- `bundle.active` is `true` in the committed `tauri.conf.json` so
  `tauri build` produces installer artefacts on any machine — signing
  is optional (missing identities yield unsigned bundles that still
  run with an OS warning).
- Dropped the unused `network_allow` field from `WasmPlugin` /
  `WasmProvider`. Will be re-introduced when WASI p3 sockets stabilise.
- `README.md` synced with the actual implementation: removed the
  stale `tantivy` mention, called out Ollama streaming and Ed25519
  plugin signing.
- `plugin-sdk/examples/music-recognizer/README.md` rewritten from a
  placeholder stub into real install/build instructions.

## 0.1.0 — initial release target

Initial public target; see `docs/plan.md` for the architecture
overview. Ship criteria:

- ⌘⇧Space capture → OCR → Ollama translate → overlay, with intent
  detection (QR / text / photo / mixed) and intent-aware action
  ribbon.
- Lens Window mode with pinned region watcher (average-hash change
  detection + auto re-translate).
- Live subtitle pipeline (cpal loopback → whisper.cpp → translate →
  subtitle window) with configurable chunk/overlap seconds.
- Plugin system: WebAssembly Component Model and JSON-RPC sidecar
  plugins, Ed25519 signature verification, AudD music-recogniser
  example.
- Settings hot-reload via `notify` watcher; schemars-generated
  settings form; provider chains with per-task timeouts, fallback
  conditions, stickiness, and global `allow_cloud` gate.
- macOS permission onboarding with live Screen Recording +
  Accessibility detection via CoreGraphics / ApplicationServices.

Test coverage at 0.1.0 target:

- 163 Rust unit tests + 23 integration tests (sidecar RPC, plugin
  registry discovery, storage persistence, settings file
  round-trip, pipeline chain, WASM host load-time, WASM real `run`).
- 14 plugin SDK tests + 20 music recogniser tests.
- 49 Vitest (logic + Svelte component render).
- Clippy `-D warnings`, `cargo fmt --check`, `npm run check` all
  clean across Linux, macOS and Windows.
