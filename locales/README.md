# 言語ファイル

UI 文言の一覧。1 言語 1 ファイル（`<言語コード>.json`）、画面側（`src/`）と Rust 側（`src-tauri/src/`）の共用。
ビルド時に本フォルダーの全ファイルをアプリへ組込み。

## 構成

- 項目：キー ID → 文言。キー ID は全言語ファイルで共通。
- キー ID：`区分:名称`（英小文字・数字・`-`・`_`）。区分は使用箇所（例：`settings`・`history`）、
  複数箇所で共用する文言は `common`。
- `ja.json`：基準の言語。キーの一覧と `{name}` の基準、文体検査（`npm run lint:copy`）の対象。
  他言語のファイルに無いキーは日本語で代替表示。
- `@language`：当該言語での言語名（例：`English`）。設定画面「表示言語」の選択肢に表示。
- `{name}`：値の埋込み箇所。全言語で同一の名称（語順の変更は可能）。
- 項目は符号位置順（`npm run lint:i18n -- --fix` で自動整列）。

```json
{
  "@language": "English",
  "common:save": "Save",
  "history:count": "{n} items"
}
```

## 言語の追加

1. `en.json` を複製し、ファイル名を言語コード（例：`fr.json`、OS の言語コードの先頭部分と同一）へ変更。
2. `@language` と全項目の文言を翻訳（キー ID は変更不可）。
3. `npm run lint:i18n` で過不足を確認。

ソースの変更は不要。設定画面の選択肢と「自動（OS の言語）」の判定へ自動で反映。
OS の言語に該当するファイルが無い環境は英語で表示。

## 文言の追加・変更

1. 全言語ファイルへキー ID と文言を追加（変更は該当項目の文言を編集）。
2. ソースからキー ID で参照（画面側：`t('区分:名称')`、Rust 側：`tr!("区分:名称")`）。

ソースへの日本語の直接記述、未登録・未使用のキー、言語間の過不足は `npm run lint:i18n` が検出（CI で毎回実行）。
規約：`CLAUDE.md`「表示言語」。
