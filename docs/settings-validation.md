# 設定の検証と自動修正

`config.toml` の不正値を起動時・再読込時に検出し、ホームに警告と修正案を表示する仕組み。
実装：`src-tauri/src/settings/validate.rs`（検査・修正）、`settings/rules.rs`（移行規則）、
`src/lib/components/ConfigIssues.svelte`（表示）。

## 処理の流れ

対象は利用者の `config.toml` の生 TOML（既定値は対象外）。修正は利用者の記述箇所のみ変更。

| 段階 | 内容 | 適用 |
| --- | --- | --- |
| 1. 移行規則 | 項目名変更・廃止項目・旧プロバイダー識別子（`rules.rs`） | 自動。`config.toml.bak-<時刻>` に退避し、ホームに通知 |
| 2. スキーマ検査 | 未知の項目・型不一致・選択肢外・範囲外（`Settings` の JSON Schema） | 提案のみ |
| 3. プロバイダー検査 | チェーン内の未登録・機能非対応の識別子（登録済み一覧から動的判定） | 提案のみ |

段階 2・3 の結果は `list_config_issues` で取得、`apply_config_fixes` で適用（退避後に書込・再読込）。
読込自体は従来どおり失敗せず、不正値のみ無視して他の値を使用。

### 修正案の種類

| 問題 | 修正案 |
| --- | --- |
| 未知の項目 | 近似名（編集距離 2 以下）があれば改名、なければ削除 |
| 選択肢外 | 大文字・小文字違いのみなら補正、他は既定値に復元 |
| 型不一致 | 整数欄の整数値の小数（`300.0`）は整数へ補正、他は既定値に復元 |
| 範囲外 | 上限・下限に補正 |
| 配列要素の不正 | 該当要素を除外 |
| 未登録・非対応プロバイダー | チェーンから除外。全要素が不正なら既定値に復元 |

## 今後の設定変更への追従

- **項目名の変更**：`rules.rs` の `renamed` に旧→新を追加。新項目に値があれば旧値は破棄。
- **項目の廃止**：`removed` に追加。
- **プロバイダー識別子の変更**：`provider_aliases` に追加（`tasks` で対象チェーンを限定可）。チェーンを置換し、旧識別子の
  `providers.configs.<旧>` は旧エンジン用のため削除。
- **範囲の宣言**：`schema.rs` の該当欄に `#[schemars(range(min = .., max = ..))]`。
  設定画面（`settings-meta.ts`）の範囲と一致させる。
- **新しい項目・選択肢**：スキーマから自動で検査対象。追加作業なし。
- **既定値のみの変更**：従来どおり `migrate.rs`（旧既定値と一致する場合のみ更新）。

規則の追加時は `settings::validate::tests` に旧形式の例を追加。
`tests/fixtures/config/pre-release-full.toml` は公開前の版が書き出した実ファイル（全既定値の複製）。
