# 文字認識モデルの選定（2026-11）

文字認識は PaddleOCR 系モデル（検出＋認識の 2 段構成）を、ONNX Runtime または rten で実行する
（`src-tauri/src/providers/ocr_ppocr.rs`）。本書は標準モデルの世代更新と、
追加の文字体系の認識方式を決定した際の計測方法と結果の記録。

## 結論

| 用途 | モデル | 取得量 |
| --- | --- | ---: |
| **標準**（日本語・中国語・ラテン文字） | **PP-OCRv6 small**（検出・認識） | 31 MB |
| 追加の文字体系（任意取得） | PP-OCRv5 mobile の文字体系別認識モデル 7 種 | 各 8〜13 MB |

- PP-OCRv6 small は PP-OCRv5 mobile と比較し、日本語の文字誤り率が 1.46% → 0.56%、処理時間も約 2 割短縮。
- PP-OCRv6 tiny は辞書に仮名を含まず、日本語は読取不能のため不採用。
- PP-OCRv6 の辞書はハングル・キリル文字・アラビア文字・タイ文字・インド系文字を含まない。
  これらは PP-OCRv5 世代の文字体系別モデルで対応（PP-OCRv6 世代の同種モデルは未公開）。
- 全モデルは PaddlePaddle 公式の ONNX 配布物（Apache-2.0）。コミットと SHA-256 で固定。
  辞書は各モデルの `inference.yml` から抽出し、アプリへ同梱（`ocr_dicts/`）。

## 方法

- **実行環境**：クラウドの x86 CPU 4 コア（GPU なし）。アプリと同一のコード
  （`cargo run --release --example ocr_eval`）、ONNX Runtime 1.24.4 の CPU 実行、検出・認識の設定値は既定。
- **評価画像**：Chromium で描画したページ 44 枚。全行の文字列と位置を正解として保持。
  - 日本語 14 枚（記事・UI・ゲーム画面・チャット。11〜36 px、明暗の単色・グラデーション・模様付き背景、ゴシック・明朝）
  - 中国語 5 枚（簡体・繁体）、英語 4 枚、4K 画面（3840 px 幅、12〜16 px）6 枚
  - 追加の文字体系 15 枚（韓国語・ロシア語・ウクライナ語・アラビア語・タイ語・ヒンディー語・タミル語・テルグ語）
- **指標**：文字誤り率（正解の各行と、その位置で認識した文字列との編集距離の合計 ÷ 正解の文字数。
  NFKC 正規化後、空白を除外）。
- **速度**：全行が新規の状態で 1 枚を読取る時間の合計（モデルは読込済）。

## 結果：世代比較

| 評価画像 | 行数 | PP-OCRv5 mobile | PP-OCRv6 small | PP-OCRv6 tiny |
| --- | ---: | ---: | ---: | ---: |
| 日本語 14 枚 | 180 | 1.46%（7.1 s） | **0.56%**（5.8 s） | 57.18% |
| 中国語 5 枚 | 52 | 2.10%（2.4 s） | **0.40%**（2.1 s） | 6.50% |
| 英語 4 枚 | 48 | 0.20%（1.8 s） | **0.00%**（1.6 s） | 0.20% |
| 4K 日本語 3 枚 | 156 | 4.29% | **0.97%** | — |
| 4K 英語 2 枚 | 48 | 34.62% | **1.09%** | — |
| 4K 中国語 1 枚 | 20 | 0.00% | 0.00% | — |

- 検出・認識の片方のみ更新した場合も測定：日本語は認識のみ更新で 0.73%、検出のみ更新で 1.53%。
  改善の大半は認識モデル、4K の小文字は検出モデルの寄与。
- PP-OCRv6 small に残る誤読の大半は「〜」と「~」、絵文字など、翻訳結果へ影響しない差異。
- 既存の評価画像（`tests/fixtures/lens`、英語中心の 11 枚）では未認識の文字が 0.18% → 0.40%。
  差分は 4K 画像のメニュー 1 行（PP-OCRv6 の検出漏れ）で、他の 10 枚は同等以上。
- 検出の閾値は PP-OCRv6 の公式値（0.2／0.45／1.4）も測定したが、既定値との差は誤差範囲のため変更なし。
- rten での実行も同一の認識結果（日本語 14 枚：11.9 s → 11.3 s）。
- DirectML（Windows の GPU）での動作は未検証。読込時の実測で失敗・低速の場合は CPU 実行を自動選択するため、
  動作不能にはならない。

## 結果：追加の文字体系

標準モデルは未知の文字体系の行を、空文字または行内の数字・記号のみとして出力する
（数字を含む韓国語の行は、数字のみを高い信頼度で出力）。信頼度のみでは判別不能のため、次の規則を採用。

1. 標準モデルの読取が不確実な行（信頼度 0.85 未満、または行長に対し文字数が過少）を、取得済の追加モデルで再認識。
2. 追加モデルの結果は、信頼度 0.8 以上・当該文字体系の文字が過半・標準側が不確実または文字数 85% 未満の場合のみ採用。
3. ある文字体系が画面内に存在する間は、新規行を全てその追加モデルでも認識（数字のみ出力された行の救済）。

| 文字体系（評価画像） | 追加モデルなし | 追加モデルあり |
| --- | ---: | ---: |
| 韓国語 3 枚 | 84.95% | 1.29% |
| ロシア語 3 枚 | 95.42% | 0.00% |
| ウクライナ語 1 枚 | 96.75% | 0.00% |
| アラビア語 2 枚 | 100.00% | 1.89% |
| タイ語 2 枚 | 93.27% | 0.00% |
| ヒンディー語 2 枚 | 98.95% | 2.09% |
| タミル語 1 枚 | 97.84% | 0.72% |
| テルグ語 1 枚 | 98.55% | 1.45% |

- 7 種を全て取得した状態でも、日本語・中国語・英語の 29 枚（436 行）は認識結果が不変、
  処理時間も同等（日本語 14 枚：6.0 s → 6.1 s）。追加モデルが日中英の行を置換した例は 0 件。
- 韓国語のみ取得した場合、韓国語 3 枚（24 行）の読取は 1.0 s → 1.6 s。
- キリル文字は `cyrillic`（365 字）と `eslav`（76 字）が同精度のため、対象言語の広い `cyrillic` を採用。
- アラビア文字のモデルは左から右の並びで出力するため、記述順へ並替（数字・ラテン文字の並びは維持）。
- ギリシャ文字のモデルも公開済だが、翻訳モデル（PLaMo 3 Translate）の対象外言語のため除外。

## 再計測

```sh
cd src-tauri
cargo run --release --example ocr_eval -- <モデルのフォルダー> <出力先> <画像>...
```

1 枚ごとに認識行（文字列・位置・信頼度）と読取時間を JSON で出力。検出の設定値は環境変数
（`PPOCR_DET_THRESHOLD` 等）で変更可能。文字体系別の代表画像と正解は `tests/fixtures/ocr` に同梱。
